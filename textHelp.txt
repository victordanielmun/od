rea el frontend base del RPG multijugador con React, Vite y Phaser, incluyendo sistema de personajes 2D, lobby de misiones y organización de UI.

PREREQUISITO:
Fases 1-4 del backend completadas.

OBJETIVO DE LA FASE:
- Sistema completo de personajes 2D con sprites animados
- Lobby visual donde seleccionar misiones
- 3 misiones de prueba (salas) con mapas diferentes
- Layout organizado: canvas del juego, chat, lista de usuarios, video grid
- Integración WebSocket para movimiento en tiempo real

STACK FRONTEND:
- React 18 + Vite
- Phaser 3 (rendering 2D y físicas)
- Zustand (estado global)
- Tailwind CSS (UI)
- WebSocket nativo

FEATURES DETALLADOS:

=== 1. SISTEMA DE PERSONAJES 2D ===

A. Clases de Personajes (3 para validar):
   
   Warrior (Guerrero):
   - Health: 150
   - Speed: 100
   - Attack: 20
   - Range: 50 (melee)
   - Habilidad: "Slash" (ataque en área)
   
   Mage (Mago):
   - Health: 80
   - Speed: 90
   - Attack: 30
   - Range: 200 (ranged)
   - Habilidad: "Fireball" (proyectil)
   
   Archer (Arquero):
   - Health: 100
   - Speed: 120
   - Attack: 25
   - Range: 300 (ranged)
   - Habilidad: "Arrow Rain" (múltiples flechas)

B. Sprites y Animaciones:
   
   Cada personaje necesita spritesheets con:
   - idle: 4 frames (respiración estática)
   - walk: 6 frames por dirección (up, down, left, right)
   - attack: 8 frames
   - hit: 3 frames (recibir daño)
   - death: 5 frames
   
   Formato recomendado:
   - Tamaño: 32x32 o 48x48 píxeles por frame
   - Spritesheet horizontal o grid
   - PNG con transparencia
   
   Fuentes de sprites gratuitos:
   - itch.io (buscar "2D character sprite")
   - OpenGameArt.org
   - Craftpix.net (free section)

C. Clase Player en Phaser:
   
   Propiedades:
   - sprite: Phaser.GameObjects.Sprite
   - username: string
   - characterClass: "warrior" | "mage" | "archer"
   - health: number
   - maxHealth: number
   - speed: number
   - direction: string
   - isMoving: boolean
   - isAttacking: boolean
   - body: Phaser.Physics.Arcade.Body
   
   Métodos:
   - update(time, delta): actualizar estado cada frame
   - move(direction): mover en dirección
   - attack(): ejecutar ataque
   - takeDamage(amount): recibir daño
   - playAnimation(name): reproducir animación
   - setPosition(x, y): actualizar posición
   - destroy(): limpiar recursos

D. Clase RemotePlayer:
   
   Similar a Player pero:
   - Sin control de input (controlado por red)
   - Interpolación suave de movimiento
   - Buffer de posiciones para smooth movement
   - Solo reproducir animaciones basadas en datos recibidos

=== 2. LOBBY Y SISTEMA DE MISIONES ===

A. Lobby Scene (LobbyScene.js):
   
   Mapa del Lobby:
   - Área de 2000x1500 píxeles

   - 3 portales/puertas para misiones

   - Decoración: árboles, edificios, bancos
   
   NPCs en Lobby:

   - NPC 2: "Character Trainer" → permite cambiar clase

   Interacción con NPCs:

   - Presionar E abre diálogo/UI

B. Misiones (3 para validar):
   
   Misión 1: "Forest Patrol" (Patrulla del Bosque)
   - Mapa: Bosque de 3000x2000 píxeles
   - Objetivo: Eliminar 5 slimes
   - Enemigos: Slimes (lentos, bajo daño)
   - Recompensa: 50 XP

=== 3. MAPAS Y GENERACIÓN ===

A. Usar Tiled Map Editor (https://www.mapeditor.org/):
   
   Instalación:
   - Descargar e instalar Tiled
   - Crear nuevo mapa: Orthogonal, 32x32 tile size
   
   Capas del mapa:
   1. Ground: suelo base (pasto, tierra, piedra)
   2. Walls: paredes y colisiones
   3. Objects: decoración (árboles, rocas, cofres)
   4. Collision: capa invisible para colisiones
   5. Spawn Points: capa de objetos para puntos de spawn
   
   Exportar:
   - File → Export As → JSON
   - Guardar en /src/assets/maps/

B. Tilesets gratuitos recomendados:
   - LPC (Liberated Pixel Cup): sprites de 32x32
   - Kenney.nl: tilesets variados
   - itch.io: buscar "tileset rpg"

C. Cargar Mapas en Phaser:
```javascript
   // En PreloadScene
   this.load.tilemapTiledJSON('lobby', '/assets/maps/lobby.json');
   this.load.image('ground_tiles', '/assets/tilesets/ground.png');
   this.load.image('walls_tiles', '/assets/tilesets/walls.png');
   
   // En LobbyScene
   const map = this.make.tilemap({ key: 'lobby' });
   const groundTileset = map.addTilesetImage('ground', 'ground_tiles');
   const wallsTileset = map.addTilesetImage('walls', 'walls_tiles');
   
   const groundLayer = map.createLayer('Ground', groundTileset, 0, 0);
   const wallsLayer = map.createLayer('Walls', wallsTileset, 0, 0);
   
   // Configurar colisiones
   wallsLayer.setCollisionByProperty({ collides: true });
   this.physics.add.collider(this.player, wallsLayer);
```

=== 5. INTEGRACIÓN WEBSOCKET ===

A. Mensajes de Personaje:
   
   Cliente → Servidor:
   - "select_character": {"character_class": "warrior"}
   - "update_position": {"x": 100, "y": 200, "direction": "right", "is_moving": true, "animation": "walk"}
   - "attack": {"target_id": "enemy_uuid", "skill": "slash"}
   
   Servidor → Cliente:
   - "character_selected": {"user_id": "...", "character_class": "mage"}
   - "position_update": {... "animation": "walk"}
   - "player_attacked": {"attacker_id": "...", "target_id": "...", "damage": 20}
   - "enemy_spawned": {"enemy_id": "...", "type": "slime", "x": 500, "y": 300}
   - "enemy_died": {"enemy_id": "..."}

B. Sincronización:
   
   En RemotePlayer.update():
   - Interpolar posición entre updates del servidor
   - Reproducir animación según "animation" recibida
   - Mostrar efectos visuales de ataque

=== 6. SISTEMA DE COMBATE BÁSICO ===

A. Ataque Melee (Warrior):
   - Presionar Espacio o Click
   - Crear hitbox temporal frente al jugador
   - Verificar overlap con enemigos
   - Aplicar daño
   - Mostrar animación de slash

B. Ataque Ranged (Mage, Archer):
   - Presionar Espacio o Click
   - Crear proyectil (sprite con physics)
   - Mover proyectil hacia cursor/dirección
   - Al colisionar con enemigo: aplicar daño y destruir proyectil

C. Enemigos (IA básica):
   - Patrullar en área definida
   - Detectar jugador en rango (300px)
   - Perseguir jugador
   - Atacar si está en rango de ataque (50px)
   - Regresar a patrulla si jugador se aleja

D. Muerte:
   - Jugador: reproducir animación death, respawn después de 5 seg
   - Enemigo: reproducir animación death, drop loot (placeholder), destruir

OPTIMIZACIONES:
- Object pooling para proyectiles y efectos
- Culling: no actualizar entidades fuera de cámara
- Limitar enemigos simultáneos (max 20 por escena)
- Usar Phaser groups para colisiones eficientes
